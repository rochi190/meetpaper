## 結論：論文的 0.2–0.6 ms 從哪來？

1. **只看同步本身（V1 真值：沒有任何量測誤差、沒有節點固定偏差）**：第 2–6 段（最差一對）
   2 節點 A / B / C = 0.09 / 0.10 / 0.10 ms，
   12 節點 = 0.32 / 0.35 / 0.48 ms；
   各組平均 0.23 / 0.24 / 0.31 ms，約是論文（0.36 / 0.41 / 0.51 ms）的 61 %。
   同步誤差的標準差只有 0.02–0.06 ms：SharkTooth 輸出是平滑直線，誤差主要是「偏一個常數」，節點越多、雜訊越大，最差一對的偏移越大。
2. **Table II 的穩態「標準差」幾乎全是量測雜訊**：A2 的 0.25 ms 用 12 mV 的 ADC 雜訊（2.4 % 振幅）就完全解釋；
   std 不隨節點數變、只隨封包長度變（A 0.25、B 0.29、C 0.37–0.41）——**時間誤差做不出這個形狀**（V1–V3 所有配置都停在 0.25 ms），
   需要一個隨封包長度增加的量測誤差（V4：244 B 時 +15 mV）。這是【推測】：BLE 發射脈衝耦合進 ×200–1600 增益的 EMG 前端，或 ISR 時間戳被長封包的 HCI 傳輸延後；模擬無法區分。
3. **mean|RSE| 隨節點數上升，主要來自「最差那一對」的固定偏差**：Eq.27 每段挑 P95 最大的一對，節點越多、挑到的偏移越大。
   需要每個節點有約 0.1 ms 的固定偏移（AFE 元件誤差的量級剛好吻合；Fig.10 收斂後各對 ±0.3 ms 的固定偏移也是它）。
   真正的同步誤差也隨節點數 / 封包長度增加（雜訊多 → δT* 不穩），但只占一部分。
4. **第 1 段大、之後收斂 = SharkTooth 的起始收斂**：V1 真值第 1 段 A / B / C = 0.51 / 0.55 / 0.74 ms，
   std 第 1 段 0.4–1.4 ms（論文 0.33–1.57 ms），雜訊越大越慢收斂。模擬的 A 組第 1 段比論文大（A2 0.44 vs 0.30 ms）——
   【推測】論文的 20 次重複可能在 notification 啟動後才開始計時，或起始雜訊比 Fig.12 平均值低。
5. **C12 的第 1–2 段**模擬偏低（1.03 / 0.81 vs 1.27 / 1.16 ms）：論文 C12 第 2 段 IQR 高達 0.79 ms，代表某些重複的雜訊更大或有額外事件（斷線、重連），
   用一個固定的失敗率無法重現。
6. **對「論文說 0.21–0.62 ms」的解讀**：這個數字是「同步誤差 + 量測誤差 + 節點固定偏差」的總和，而且挑最差的一對。
   模擬中 SharkTooth 自己的穩態同步誤差在 2 節點時 < 0.1 ms、12 節點 / 244 B 時約 0.3–0.5 ms（V4 真值第 6 段 C12 = 0.34 ms，含 dongle 路徑差）。
7. 2 節點的 C2 模擬 std 比論文大（0.36 vs 0.29）：論文的額外雜訊不只看封包長度，也和同一支 dongle 上的連線數有關（C2 0.30、C4 0.37）。
