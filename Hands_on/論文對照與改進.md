# Hands_on 實作 vs 論文：錯誤、差異與可以改進的地方

對照對象：Landra et al., *SharkTooth*, IEEE IoT-J 2025（Eq. 3–27、Algorithm 1–2、Section IV）。
數字來自兩次實測：`20261101_220025`（60 分鐘）、`20261101_214202`（10 分鐘），3 塊 B-L475E-IOT01A，CI 30 ms。
每個訊號的圖由 `st_signals.py` 產生，在各實驗資料夾的 `signals/`（論文原版算法：`signals_paper/`）。

## A. 實作和論文一致嗎？

**算法本身（Eq. 3–22）逐條對過，和論文一致**，`st_analyze.py` 的 `SharkTooth.step` 與 `sharktooth_sim` 的參考版相同：

| 論文 | 程式 | 結果 |
|---|---|---|
| Eq. 3、5、7、10：δT、δ²T、σ_M、λ0 | 同 | ✔ |
| Eq. 11 樞紐點（γ0 = 0、γ1 = ∞，δT1、t_P1 不重設） | 同 | ✔ |
| Eq. 9、12–14：門檻、λ（比較的是上一包的 δT\*）、γ1 + 1e-6 | 同；另外避開 ∞·0 | ✔ |
| Eq. 15–17：A 其實是正規矩陣的伴隨矩陣，A·b / det(A) 直接得到 [α, β] | 同；以 t_P0 為原點（數值較穩，結果等價） | ✔ |
| Algorithm 1：t_P > t_P0 + 30 s 才更新，否則重設 A、b | 同 | ✔ |
| Eq. 23–27：共同 t_P 格點 50 Hz、每秒平均、在 t_P 軸量真實延遲、P95 最大的那一對 | 同（`st_table2.py`） | ✔ |

**刻意和論文不同的地方**（README 第 10 節有寫）：

| 差異 | 為什麼 | 影響（60 分鐘那次） |
|---|---|---|
| 預傾斜 +100 ppm（`--tilt`） | 這三塊板子的 α 是 −44 / −47 / −35 ppm，論文的算法在負漂移下不能用（見 B-3） | 用論文原版（`--paper`）：樞紐點 515 / 479 / 427 次，**有輸出 0 % / 0 % / 0.7 %**；加預傾斜：6 / 6 / 3 次，99 % |
| 穩定期保留上一組 α、β | 論文 Eq. 18 令 α = β = 0，t̂_S 會跳回 t_P（見 B-4） | 只影響換樞紐點後的 30 s |
| tick 用精確的 1/32768 s | 論文韌體用 30.51 µs，等於人為加 +248 ppm | 這正是論文沒遇到負漂移的原因 |
| 真實延遲預設用正弦擬合 | 論文用 10 kHz 升頻互相關，解析度 0.1 ms | std 從 0.05 變 0.06–0.07 ms（`--gt cc` 可切換） |

**這次修掉的問題**：

1. `st_table2.py` 只算兩個指標；論文 Section IV-B 是**三個**（Absolute Average、Standard Deviation、**95th percentile**，P95 畫在 Fig. 12）。已加上 P95。
2. 真實延遲只有正弦擬合，和論文的數字不能直接比 → 加 `--gt cc`（照 Eq. 25 的 10 kHz 互相關）。
3. 兩次錄音各跑一次 `st_table2.py` 會寫到同一個 `Hands_on/rse_table.png`，互相覆蓋 → 單一資料夾時改輸出到該資料夾，並加 `--out`。
4. 表格標題漏字（ACROSS **DIFFERENT CONFIGURATIONS** AND ACQUISITION SEGMENTS）。
5. `--tick-us` 的說明寫「約 −248 ppm」、README 寫「+248 ppm」：兩個都對但指的東西不同（t_P 的換算誤差 vs δT 的斜率），已在說明裡寫清楚。
6. 原本只有 Fig. 6、Fig. 9；論文的 Fig. 3（σ100）、Fig. 10（每對 RSE）、Fig. 12（P95 對 σ²100），以及算法的中間訊號、ADC 訊號本身都沒有圖 → `st_signals.py`。

## B. 論文本身的錯誤或疑點

1. **Eq. 17 的條件寫錯**：第二種情況寫 `A^{i−1}_{0,0} ≥ 0`，和第一種 `= 0` 重疊；應和 Eq. 16 一樣是 `≠ 0`（筆誤）。
2. **Eq. 7 差一**：Σ 從 n = i−M 到 i 共 M+1 項，卻除以 M。實作上沒差，但式子不嚴謹。
3. **Eq. 11 的樞紐點 = δT 的全域最小值，隱含 α ≥ 0**。α < 0 時下緣一直往下走，每隔幾秒就出現新的最小值 → γ0 歸零、30 s 穩定期重來 → 永遠沒有輸出（`signals_paper/NODE_*_2_algorithm_signals.png`：樞紐點每 ~7 秒一次，γ0 從 0 往下收斂到一半又被重設，到不了 −44 ppm）。
   晶振誤差正負都可能（±20 ppm 晶振 + PC 時鐘誤差，模擬 T14 的「物理時鐘」設定中約 38 % 的節點是負的）。論文的板子因為 30.51 µs 的 tick 常數被加了 +248 ppm，才沒碰到這個問題；論文沒有提到這個前提。
4. **Eq. 18 穩定期內 α = β = 0**：t̂_S = t_P，和前後的輸出差了一個 β（這次 10 / 72 / 120 ms）。即時系統裡這是一個很大的跳動；配合第 3 點，負漂移時幾乎一直處在這個狀態。保留上一組 α、β 比較合理。
5. **λ0（Eq. 10）大多數時候是 1**：BLE 的延遲本來就均勻分布在一個 CI 內，所以 σ_M ≈ CI/2（實測 σ100 = 14.7 ms，CI/2 = 15 ms，論文 Fig. 3c 也這樣說），CI/(2σ) ≈ 1 → λ0 被截在 1。Eq. 13 的「依變異度調整權重」只有在重傳很多時才會作用；60 分鐘那次：λ0 = 1 的時間占 64–70 %，實際用到的 λ 有 85–90 % 是 0.5（`NODE_*_2_algorithm_signals.png` 第 4 列）。另外只有約 2 % 的封包是「合格點」會更新 γ0，其他 98 % 只讓 γ1 往上加。
6. **Eq. 14 的增量是「每一包」1e-6**：等於 10 Hz 時每秒 +10 ppm。換封包率（論文自己也說是為 10 Hz 調的）門檻的行為就變了；寫成「每秒」才和封包率無關。
7. **迴歸對象是 δT\*（模型輸出），不是資料**：δT\* 是一條斜率被平滑的折線，對它做 OLS 等於把 γ0 的歷史做加權平均；論文用「同質變異、OLS」來說明並不貼切。另外從上一個樞紐點起全部等權累加、沒有遺忘因子，α 隨溫度變的時候會越來越慢跟上（模擬 T12）。
8. **Eq. 27 只取最差的一對，會讓「節點越多越差」被高估**：節點對數是 C(N, 2) = 1、6、15、28、45、66（N = 2…12）。取越多對的最大值，本來就會越大，即使每一對的分布完全一樣。論文把趨勢全部歸因於網路壅塞，但其中一部分是統計上的取最大值。
   實測 3 節點、3 對：每一段「最差那對」的 mean|RSE| 比「所有對平均」大 24–43 %（`signals/summary.md`）。
9. **真實延遲的量測**：
   - 互相關解析度 0.1 ms，和要報告的數字（0.2–0.3 ms）同一個量級，會墊高 std。
   - 量到的是「整條訊號路徑」的延遲差，包含各節點 AFE 的類比延遲差，不只是同步誤差。
   - 正弦週期 200 ms，延遲差只能分辨 ±100 ms；SharkTooth 還沒輸出時（α = β = 0）的 epoch 要怎麼算，論文沒寫清楚。
10. **開頭的暫態比 Table II 看起來大**：10 分鐘那次，單一節點的同步誤差在前 200 秒達到約 −2 ms（`20261101_214202/signals/NODE_A_4_waveform.png` (f)），節點對 RSE 到 1.5 ms（`pairs_1_rse.png`）。論文第 1 段（0–600 s）的平均值把這段平均掉了；即時應用要注意前幾分鐘。

## C. 可以改進的地方

**實驗**

1. 照論文：每組設定錄 **1 小時 × 20 次**，`st_table2.py` 給多個資料夾，才有 IQR；10 分鐘那次只有第 1 段。
2. 加做 2 節點（對照論文 A2），以及報「所有對的平均」和「最差那對」兩種（`st_signals.py` 的 summary 已列）。
3. 取樣率是 50.57 Hz、封包間隔 98.9 ms，因為 TIM6 用 MSI。STM32L4 可以開 **MSI PLL 模式（RCC_CR 的 MSIPLLEN）讓 MSI 鎖到 LSE**，取樣率會變成精確的 50 Hz、封包 100 ms，和論文一樣。時間戳本來就用 LSE，所以同步結果不受影響，只是比較好對照。
4. 記錄溫度（或至少室溫），對照 α 的漂移。
5. 用 `events.csv` 的「迴圈延遲 > 5 ms」標出可能被延後的 t_C，看它們和 ε 的尖峰是否重疊。

**算法（論文沒有，但值得試）**

1. 取代預傾斜的根本解法：樞紐點不要用全域最小值。例如
   - 用前 N 秒的下緣（下凸包或 5 % 分位數迴歸）先估一個初始斜率，樞紐點改成「低於目前 δT\* 直線」的點；
   - 或只有低於 δT\* 超過 k·σ_M 才算新樞紐點，否則當成一般的合格點（Eq. 12）。
2. 遞迴 OLS 加遺忘因子（模擬 `forget = 0.999`，T5），跟得上溫度漂移。
3. Eq. 14 的增量改成每秒、與封包率無關。
4. 穩定期保留上一組 α、β（已是預設），或在新舊估計之間平滑過渡，避免 t̂_S 跳動。
