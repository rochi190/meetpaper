## 1. SharkTooth 核心演算法狀態機修正（Eq. 11、12）

原先輸出將幾何探針初始斜率寫成不存在的 $\gamma_1 = 10^{-8}$，且將探針起點誤植為當前樣本點 $\delta T^i$。這徹底破壞了論文依賴「下界幾何切線」過濾重傳雜訊的初衷。

### Eq. (11) 原文正確定義（§III-C / p.46181）
當發現新的全域最小延遲點（Pivot Point）時：

$$\delta T^i < \delta T_0 \implies \begin{cases} \delta T_0 = \delta T^i \\ \gamma_0 = 0 \\ t_{P0} = t_P^i \\ \gamma_1 = \infty \end{cases}$$

> **【幾何原理】** 發現新 Pivot 時，$\gamma_1 \leftarrow \infty$ 代表動態探針門檻線瞬間「垂直打開」。這確保了在新的全域基準確立後，緊接著到達的第一個有效封包不會被舊的水平門檻阻擋，能無條件進入斜率初始化。

### Eq. (12) 原文正確定義（§III-C / p.46181）
當新封包小於當前動態門檻（$\delta T^i < \delta T_{thr}^i$）時：

$$\begin{cases} \gamma_0 = (1 - \lambda^i)\gamma_0 + \lambda^i \frac{\delta T^i - \delta T_0}{t_P^i - t_{P0}} \\ \gamma_1 = \gamma_0 \\ \delta T_1 = \delta T_*^i \\ t_{P1} = t_P^i \end{cases}$$

> **【幾何原理】** 遇到合格點後，探針斜率重設為當前模型斜率（$\gamma_1 = \gamma_0$），且探針垂直起點必須設為**當前下界校正線的預測值 $\delta T_*^i$**，而非原始噪訊點 $\delta T^i$！探針是從「平滑下界線」出發向上仰角掃描，若將起點設在 $\delta T^i$，門檻會直接被該點的局部抖動墊高，失去下邊界約束力。

### 修正後的 Python 核心判斷片段：

```python
# 情況 A: 找到全新 Pivot (Eq. 11)
if delta_T < self.delta_T_0:
    self.delta_T_0 = delta_T
    self.t_P0 = t_P
    self.gamma_0 = 0.0
    self.gamma_1 = float('inf')  # 原文為無窮大
    # 觸發 30 秒冷卻重設 (Eq. 18)
    self.A.fill(0.0)
    self.b.fill(0.0)
    self.alpha = 0.0
    self.beta = 0.0
else:
    # 情況 B: 與動態門檻比較 (Eq. 9)
    # 若 gamma_1 為 inf，門檻為 inf，必定合格
    delta_T_thr = (
        self.delta_T_1 + self.gamma_1 * (t_P - self.t_P1)
        if self.gamma_1 != float('inf')
        else float('inf')
    )

    if delta_T < delta_T_thr:
        # 計算加權權重 (Eq. 13)
        lam = 0.5 * lambda_0 if delta_T >= self.delta_T_star_prev else 0.5
        denom = max(t_P - self.t_P0, 1e-6)
        # 平滑更新下界斜率
        self.gamma_0 = (1.0 - lam) * self.gamma_0 + lam * (
            (delta_T - self.delta_T_0) / denom
        )
        # 探針起點與斜率重設 (Eq. 12)
        self.gamma_1 = self.gamma_0  # 重設為當前模型斜率
        self.t_P1 = t_P
        # 先計算當前下界輸出 delta_T_star (Eq. 8)
        delta_T_star = self.delta_T_0 + self.gamma_0 * (t_P - self.t_P0)
        self.delta_T_1 = delta_T_star  # 探針起點為 delta_T_*^i，非 delta_T^i
    else:
        # 遇重傳突波，探針斜率微增向上抬頭 (Eq. 14)
        self.gamma_1 += 1e-6
        delta_T_star = self.delta_T_0 + self.gamma_0 * (t_P - self.t_P0)
```

## 2. Nature 論文冪律公式指數校正（Fig. 2f、2g）

原論文 **Fig. 2 內嵌公式（p.705）** 的精確數值為：

* **離散手勢分類（Fig. 2f）：**
  $$f(N, D) = 3.5 + 11.4 N^{-0.34} + 1.8 D^{-0.17}$$
  （先前誤植為 $-0.47$，正確為 **$-0.17$**，代表手勢任務中參數量對錯誤率的下降邊際效益比受試者數量更早趨於平緩。）

* **手寫字元轉錄（Fig. 2g）：**
  $$f(N, D) = 2.1 + 26.1 N^{-0.36} + 3.6 D^{-4.04}$$
  （先前遺漏數字 4 寫成 $-0.04$，正確為 **$-4.04$**。高達 $-4.04$ 的冪次反映出 Conformer 模型大小在端到端 CTC 語意解碼中具有極端陡峭的效能門檻，模型容量不足時 CER 會呈斷崖式上升。）

## 3. Nature 論文個人化學習率 $\text{LR}(N)$ 單位與數值校正

在原論文 **Methods - Personalized modelling - Optimization（p.714）** 中：

$$\text{LR}(N) = 1.24 \times 10^{-5} \times N^{-0.42}$$

> **【原文】** "...with $N$ being the number of pretraining participants." (p.714)

在 Fig. 2 的 Scaling 曲線中，$N$ 的繪圖單位是「百人（hundreds of participants）」；但在 p.714 的微調學習率回歸公式中，$N$ 帶入的是受試者絕對人數（如 25, 400, 6527）。

* **當預訓練人數為 6,400 人時（$N = 6400$）的逐步計算：**
  $$6400^{-0.42} = \frac{1}{6400^{0.42}} \approx \frac{1}{39.467} \approx 0.025338$$
  $$\text{LR} = 1.24 \times 10^{-5} \times 0.025338 \approx \mathbf{3.14 \times 10^{-7}}$$

先前誤帶入 $N=64$ 計算出的 $2.16 \times 10^{-6}$ 比真實最佳微調學習率大了將近一個數量級，以該學習率微調高達 60M 參數的 Conformer 會導致預訓練特徵嚴重損壞（Catastrophic Forgetting）。

## 4. SASG-DA Table II 評估欄位與準確率校正

在 SASG-DA 論文 **Table II（p.8936）** 中，DB7 資料集在 STCNet 骨幹下，SASG-DA 的四個指標排列為：
* **Accuracy (Acc):** $\mathbf{82.15 \pm 4.59\%}$
* **Precision (Pre):** $83.07 \pm 3.98\%$
* **Recall (Rec):** $82.68 \pm 4.14\%$
* **F1-score (F1):** $82.87 \pm 4.13\%$

先前的教材將第 1 欄與第 2 欄對調，誤把 Precision 的 83.07% 當作 Accuracy，並計算出 $+9.46\%$ 的增益。
* **正確數值：** DB7 上 STCNet 的分類準確率為 **$82.15\%$**（對比 Baseline 的 $73.61\%$，實際增益為 **$+8.54\%$**）。這與 Table V 消融實驗中的 $82.15\%$ 完全吻合。

## 5. SharkTooth 圖表物理意義與文獻對比修正

* **Fig. 4 突波物理高度校正（§III-A / p.46178–46179）：**
  Fig. 4(a) 中 $\delta T$ 的縱軸基準線約在 $1.18\text{–}1.20\text{ s}$，這段常數是周邊與主機啟動瞬間產生的**初始時鐘偏移 $\beta$**（Clock Offset）。重傳引起的抖動是疊加在該基線上向上竄升至 $1.35\text{–}1.40\text{ s}$ 的短暫毛刺。
  > **【物理修正】** 突波的實際延遲增量為 $1.35 - 1.20 \approx \mathbf{0.15\text{–}0.20\text{ s}}$（即約 5 到 7 個連線間隔 $\text{CI}$ 的重傳累積延遲），而非 1.4 秒的單一突波。

* **Table III 文獻橫向對比修正（§V-B / p.46187–46189）：**
  先前稱 SharkTooth 是「唯一兼具連線模式、線上運作且隨資料封包同步」的說法有誤。
  > **【文獻事實】** 論文 Table III 明確列出 **Li et al. [25]（Sensors 2023）** 同樣採用 Connection 模式、支援 Online 運作、且同樣支援 Sync via Data Packets。
  > **【SharkTooth 真正貢獻】** 是將此架構從 Li et al. 僅驗證的 **2 個節點（且未考慮重傳突波）**，大幅推進至 **12 個節點**，並在重度封包碰撞與重傳環境下，透過下界幾何探針維持 $0.21\text{–}0.62\text{ ms}$ 的亞毫秒級精度。

## 6. 嚴格區分「原文記載」與「工程推論」

1. **Python 即時性討論：**
   * **【原文】** 論文 §II-C（p.46177）僅說明控制平台選擇 Python 是為了研究復現性與快速原型開發，並坦承「此實作並未針對時間關鍵型應用進行極致優化」。
   * **【補充推論】** 「在非即時的 Python 與通用作業系統上仍能測出 0.5 ms 精度，反向證明其演算法濾除系統抖動的強健性」，此為審稿/讀者視角的分析，非作者原文之辯護。

2. **手勢模型延遲考量：**
   * **【原文】** 論文僅在 p.712 說明 Conv1d 的 stride=10 是為了將取樣率由 2 kHz 降至 200 Hz 以利運算，並未提及「觸發延遲 <50 ms」之語句。

3. **SASS 程式碼中的梯度裁剪：**
   * **【原文未說明】** 原文 §IV-D（p.46181）僅列出位能函數 $\Phi = \Phi_{sparsity} + \Phi_{diversity}$ 與梯度步長 $\eta = 10.0$，**完全未提及使用 `clip_grad_norm_`**。先前實作中的梯度裁剪屬於 PyTorch 數值防禦程式設計，重現原文基準線時應以未裁剪之純 SGD 實作為準。
